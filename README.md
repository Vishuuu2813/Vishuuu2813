<summary><b>🏗️ How I approach a build</b> (click to expand)</summary>

<br />

1. **Understand the business first** — who pays, what breaks, what "done" actually means.
2. **Design the data** — schema and flows before pixels, because bad models cost the most to fix.
3. **Ship a thin vertical slice** — one real flow end to end, in production, early.
4. **Harden it** — validation, error states, loading states, logging, atomic writes.
5. **Stay on it** — measure, iterate, delete features nobody uses.

</details>
